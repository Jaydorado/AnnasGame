# TriPeaks Solitaire PWA — Design

Date: 2026-09-26. Status: design approved in chat by Jay; spec awaiting review.

## Goal

A Disney-Solitaire-inspired TriPeaks game for one player (Jay's girlfriend) on an Android phone. Installed from a URL as a PWA, fully offline. Earn-only progression: no microtransactions, no waiting.

Inspiration: SuperPlay's *Disney Solitaire* (TriPeaks with streaks, Wild / Undo / +5 boosters, level map). Her main complaint about it — having to wait for or buy gold — is the thing this game must not do.

## Hard constraints

- **No pay, no wait.** No real-money store, no lives/energy, no timers, no daily caps, no ads, no premium currency. Retrying any level is instant and free. Losing never costs coins.
- **Every level is winnable without boosters**, proven by a solver in the test suite.
- **No Disney IP** in the repo or build: own art only.
- **Offline after first load**; progress persists on the device.
- Target: Android Chrome (current), portrait, viewport ≥ 360×640 CSS px.

## Scope

In v1:
- TriPeaks core play, streaks, win/lose.
- Boosters: Undo, Wild card, +5 cards — bought with earned coins.
- 25 hand-authored levels on a scrolling level map, 1–3 stars each.
- Coins earned by play, persisted.
- Own Disney-inspired art (code-drawn), CSS animations, sparkle/confetti effects.
- PWA install + offline, hosted on GitHub Pages.

Out of v1 (possible later): special tiles (puzzle pieces, frames, carriage/wands), Runner cards, stars→scene-rebuild meta, sound/music, cloud sync/accounts, iOS save export, real Disney images.

## Stack

TypeScript + Vite. Cards are DOM elements positioned with CSS transforms. `vite-plugin-pwa` (auto-update service worker, manifest). Vitest for tests. No UI framework, no game engine. GitHub Actions builds and deploys to GitHub Pages.

## Architecture

```
src/
  core/                 pure TS; no DOM, no timers, no Math.random
    cards.ts            Card { rank: 1..13, suit: 0..3 }; canPlay(card, top)
    rng.ts              seeded PRNG (mulberry32) + Fisher–Yates shuffle
    layout.ts           Layout / Slot types; faceUp(slot, removed)
    layouts/            named layout data (threePeaks, pyramid, diamond, twinPeaks, fan)
    game.ts             GameState, newGame(level), reducer(state, action) -> state
    economy.ts          coin constants and reward/cost functions
    solver.ts           boosterless solvability check (tests + level authoring)
  levels/levels.ts      the 25 level definitions
  progress/save.ts      versioned localStorage persistence
  ui/
    render.ts           board DOM, card elements, transitions
    hud.ts              coins, streak, stock count, booster buttons
    map.ts              level map screen
    dialogs.ts          win / out-of-moves dialogs
    fx.ts               sparkles, confetti, star animation
    art/                SVG card faces/back, palette CSS
  config.ts             credit text and tunables not in economy.ts
  main.ts               screen router: map ↔ level ↔ result
public/                 icons; manifest generated by vite-plugin-pwa
tools/findSeeds.ts      dev script: search seeds that the solver accepts
```

Data flow: UI dispatches an action → `reducer` returns a new `GameState` → UI diffs old vs new and animates changed cards. `core/` never imports from `ui/`. Coins earned in a level are applied to the save when the level ends (win, loss, or quit) and on `visibilitychange: hidden`, so an app kill keeps them.

## Game rules

**Deal.** A level supplies `layoutId`, `seed`, `stockSize`. A standard 52-card deck is shuffled with `seed`. The first `layout.slots.length` cards go to the table in slot order; the next `stockSize` go to the stock. Then the top stock card moves to the discard pile. Constraint: `slots.length + stockSize ≤ 52`.

**Layout.** Each slot has `x, y` (layout units, rendered scaled to the viewport), `z` (draw order) and `coveredBy: slotIndex[]`. A table card is face-up and playable iff every slot in its `coveredBy` has been removed. Suits are shown but never matter to rules.

**Play.** `canPlay(card, top)`: ranks differ by exactly 1, with King–Ace wrapping (K↔A). If the top of the discard pile is a Wild, any card can be played. Playing moves the card from the table to the discard pile.

**Draw.** Tapping the stock moves its top card to the discard pile and resets the streak to 0. Disabled when the stock is empty.

**Streak.** +1 per table card played; reset only by Draw. Wild placement does not reset it.

**Win.** Table empty. **Out of moves.** Stock empty and no face-up table card is playable (a Wild on top always makes a move available, so this never triggers with a Wild on top).

## Economy (initial tuning; constants in `core/economy.ts`)

Earning:

|Event|Coins|
|---|---|
|Table card played|+1|
|Streak reaches a multiple of 5 (5, 10, 15, …)|+streak (i.e. +5, +10, +15, …)|
|Level won|+20|
|Each card left in stock at win|+2|
|First time reaching 3 stars on a level|+25|

Spending (inside a level; button disabled when unaffordable):

|Booster|Cost|Effect|
|---|---|---|
|Undo|5|Reverts the last Play or Draw, including coins that move earned. Disabled when the last action was a booster or there is nothing to undo.|
|Wild|25|Places a Wild on the discard pile. Any table card can be played onto it. Streak unchanged.|
|+5 cards|30|Adds 5 new cards to the bottom of the stock. Ranks and suits come from a seeded RNG (seed = level seed + number of +5 uses in this attempt), independent of the 52-card deal, so it works even when the deal used all 52 cards (`threePeaks` + stock 24). Always available when affordable.|

New save starts with **100** coins. Coins never go negative. Coins earned in a lost or quit attempt are kept. Replaying won levels earns coins normally (the first-time 3-star bonus pays once per level).

**Stars** (win only): 1 star for winning; 2 stars if cards left in stock ≥ `star2`; 3 stars if ≥ `star3`. Per level, `star3 > star2 ≥ 1`. A level's best star count is kept.

## Levels

Level definition:

```ts
interface LevelDef {
  id: number;          // 1..25, map order
  layoutId: LayoutId;  // 'threePeaks' | 'pyramid' | 'diamond' | 'twinPeaks' | 'fan'
  seed: number;
  stockSize: number;   // 24 early → ~16 late
  star2: number;
  star3: number;
}
```

Layouts (card counts are targets; exact coordinates are plan work): `threePeaks` 28 (classic 3-6-9-10 rows), `pyramid` 21, `diamond` ~25, `twinPeaks` ~24, `fan` ~26.

Difficulty curve: levels 1–5 `threePeaks` with stock 24; new layouts introduced one at a time; stock shrinks toward ~16 by level 25. Seeds are picked with `tools/findSeeds.ts`: shuffle candidates, keep those the solver wins without boosters, choose among them by the solver's minimum draws-needed to hit the intended difficulty. `star2`/`star3` are set from the solver's best achievable leftover stock (e.g. `star3` = best, `star2` ≈ half of best, min 1).

**Solver.** Depth-first search over (removed-slot bitmask, stock position, discard top); memoized; boosterless. Returns winnable yes/no and the maximum stock left at a win.

## Progress & save

`localStorage` key `tripeaks.save`:

```ts
interface SaveV1 {
  version: 1;
  coins: number;
  unlocked: number;                    // highest playable level id
  stars: Record<number, 1 | 2 | 3>;    // best stars per won level
  threeStarBonusPaid: number[];        // level ids
}
```

Missing, unparsable, or schema-invalid save → fresh save (100 coins, level 1 unlocked); the bad value is not thrown back to the user. Unknown future `version` → fresh save. On first run the app calls `navigator.storage.persist()`.

## Screens & UX

- **Map:** vertical scrolling winding path of 25 level nodes; each shows its best stars; locked nodes are dimmed; the current node pulses. Coin total at the top. Tapping an unlocked node starts that level.
- **Level:** table centered; stock + discard at the bottom; HUD with coins, streak meter, stock count, and the three booster buttons with prices. A back button returns to the map (coins kept).
- **Win dialog:** stars animation, coin breakdown, buttons Next / Replay / Map.
- **Out-of-moves dialog:** "Out of moves" with +5 cards (30) and Wild (25) offered if affordable, plus Retry and Map. Neutral wording; no countdowns, no pressure copy.
- **Final screen** after level 25: a thank-you with a personal credit line from `config.ts` (default `"Made with ♥ for Anna"`; Jay can change it).
- All touch targets ≥ 44 CSS px. Portrait only (manifest `orientation: portrait`).

## Art & motion

- Code-drawn SVG card faces with large rank + suit pips readable at phone size; card back is a starry night sky with a castle silhouette.
- Palette: deep night blue, gold, soft pink; background gradient with subtle twinkling stars.
- Motion: card slide to discard and flip via CSS 3D transforms (transform/opacity only); sparkle burst on each play; glowing streak meter; confetti + star pop on win. Respect `prefers-reduced-motion` by shortening/removing non-essential effects.

## Testing

Vitest, all in `core/` and `progress/`:
- `canPlay` incl. K↔A wrap and Wild top.
- Face-up computation as covering cards are removed.
- Deal determinism: same seed → same table/stock.
- Reducer: play legal/illegal, draw, streak increments/resets, win, out-of-moves detection.
- Boosters: costs deducted, disabled when unaffordable, Undo reverts board and that move's coins, Wild keeps streak and accepts any card, +5 adds 5 cards deterministically (same seed + use count → same cards), also on a full 52-card deal.
- Economy: streak bonuses at 5/10/15, win bonus, leftover-stock bonus, 3-star bonus paid once.
- Save: round trip; corrupted JSON, wrong shape, and unknown version all yield a fresh save.
- **Levels:** for each of the 25 levels, solver says winnable without boosters and `star3` ≤ solver's max leftover stock.

UI verification (not unit-tested): headless browser run on a 360×800 viewport — load map, play level 1 to a state change, use a booster, confirm manifest + service worker register and the app reloads offline.

## Success criteria

- She can install it from a URL on her Android phone and play offline.
- All 25 levels load, are winnable without boosters, and unlock in order.
- No screen ever asks her to wait or pay; boosters are affordable from play alone.
- `npm test` passes, including the per-level solver test.
